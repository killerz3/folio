The shape of it

One origin, three prefixes, two independent checks

folio serves standalone HTML documents from a single hostname. A document's URL prefix is its permission tier, so sharing something is a metadata change rather than a dashboard visit. Cloudflare Access decides who reaches the box; the box independently decides whether the document actually belongs at the path being asked for.

Neither check trusts the other. That redundancy is the whole security design, and it is what makes a single origin safe enough to keep the URLs clean.

Diagram 01 · Request path

How a request reaches the disk

Three kinds of caller arrive by three different routes. A browser carries a cookie; a remote CLI carries headers a browser can never forge; the CLI on the box skips the internet altogether. The tunnel dials outward, so the origin has no inbound port open to the world.

Diagram 02 · The re-check

The origin assumes the edge is wrong

Documents live in one canonical directory, but they are only served under the prefix matching their stored visibility. The /p/* Access policy is a blanket bypass — it lets everyone through, with no idea which document is being asked for. The origin is what stops a private document being fetched there.

Ordering hazard

The origin does not authenticate reads at all — it only checks that a document belongs at the requested path. If the DNS record exists before the Access applications do, /a/* and / are readable by anyone who knows the hostname. Create the policies first; they can exist before the record does.

Diagram 03 · Isolation

Why one origin is enough

Every serious self-hosted artifact host — artifact-server, ArtifactFlow — puts documents on wildcard subdomains so one document cannot read another or call the API. folio keeps a single origin and buys the same isolation with a header.

Documents are served under Content-Security-Policy: sandbox allow-scripts. Crucially, without allow-same-origin — which drops the document into an opaque origin. It has no origin, so there is nothing to share.

Model

Visibility is the URL

Changing who can see a document moves it between prefixes. The link changes with it — which means un-publishing genuinely kills the old link rather than leaving a URL you believe is private.

Worth remembering

shared_with in meta.json is display metadata. The real guest list is the Access policy on /t/* — editing the JSON revokes nobody.

Storage

The filesystem is the database

No Postgres, no SQLite, no migrations. A document is a directory; backup is tar; inspection is cat. Writes go to a temp file and are moved into place, so a crash mid-write can't leave a half-document.

Verification

What was actually proven

A passing suite means nothing if it cannot fail, so the check that mattered was breaking the code on purpose: forcing the visibility function to always return true turned 8 tests red. Independently, the tests were written from the spec by a separate agent that never read the implementation.

Everything below was then re-verified against the live hostname, through Cloudflare, rather than only on loopback.

  • ✓43/43 tests, including 23 traversal payloads — literal, percent-encoded, double-encoded, backslash, empty-segment
  • ✓Symlink escape — /etc/passwd linked into a document directory returns 404, verified against a live server
  • ✓A real bug caught in build — new URL() silently collapses .., so /a/doc/../neighbour/ once returned 200; parsing now works on the raw target
  • ✓Crash recovery — SIGKILL the process, healthy again in under 4 seconds
  • ✓Install is idempotent — three runs, token never rotated, documents never touched
  • ✓The edge chain, live — unauthenticated / and /a/* return 302 to Access; /api/* returns 403 to a browser; babel.kz3.dev unaffected
  • ✓The re-check survives the real edge — /p/<private-doc> returns 404 through Cloudflare: the bypass policy passed the request, the origin refused it
  • ✓Both layers are independent — a valid service token without the origin bearer gets 401; neither check alone is sufficient

Operations

Running it

folio publish report.html --id q3 --title "Q3 report" --private
folio share q3 --public          # moves it to /p/q3
folio list
folio rm q3

systemctl status folio
journalctl -u folio -f
sudo tar czf folio-docs-$(date +%F).tar.gz -C /srv/folio docs

Hardening in force

Verified live, not merely declared: runs as the unprivileged folio user with ProtectSystem=strict, NoNewPrivileges, an empty capability set, SystemCallFilter=@system-service, MemoryMax=512M, and the application directory read-only — only docs/ is writable.

Known gaps

What it deliberately doesn't do

  • ○No versioning. Publishing over a document replaces it. The layout makes a/<id>/v<n>/ cheap to add — much cheaper before there are documents worth keeping.
  • ○No comments, projects or review. That's the trade against artifact-server, which has all three and wanted a wildcard domain in exchange.
  • ○No user accounts. Access is the only identity system, which is exactly why the service is small enough to read in one sitting.
